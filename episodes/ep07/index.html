Critical PHP vulnerability: one web request can leave a ghost behind (update now)

Watch on YouTube

On 21 October 2026 the PHP project shipped fixes for two critical vulnerabilities, both rated CVSS v4.0 9.2. In the first (CVE-2026-109618), running out of memory can interrupt PHP while request data is only partly initialised, and cleanup may then treat it as valid. In the second (CVE-2026-109619), request-owned state can survive after its memory is freed, and a later request on the same worker may use it. The PHP team says a demonstrated exploit lets a single unauthenticated request trigger the attack before any application code runs (risk highest for mod_php).

Fix: update to PHP 8.5.12, 8.4.27, 8.3.36 or 8.2.35, or your vendor's patched package (backports exist for 7.4, 8.0, 8.1). The advisory's interim mitigations reduce exposure but are not a full fix.

Note: this is an official vendor advisory, not a peer-reviewed paper. No exploit details are shown in this video.
